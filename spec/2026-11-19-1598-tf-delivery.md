# Spec: git_writer delivery with branch checked out elsewhere (#1598)

## Design

In `_resolve_branch` (push path) replace `checkout -B <branch> FETCH_HEAD` with `checkout --detach FETCH_HEAD`, and push `HEAD:refs/heads/<branch>`. A detached checkout is never blocked by another worktree holding the branch, and the shared project clone's branch ref and files are not touched (Codex review: `--ignore-other-worktrees -B` would move the shared branch under the other checkout and race with cache refresh). Commit-sha reporting already uses `rev-parse HEAD`.

## Alternatives rejected

- `checkout --ignore-other-worktrees -B`: moves the branch ref the project clone has checked out; stale index and refresh race (Codex finding, confirmed).
- Detaching the project clone: touches clone logic that #1595 just fixed.

## Risks

A non-fast-forward push is rejected by origin as before. The push-path local branch no longer exists in the worktree; only `write_tests_to_branch` push=True uses it.

## Verification

Unit argv test updated; new test with a real local bare repo and a second worktree holding the branch: delivery succeeds and the second worktree's branch is untouched and the bare repo receives the commit. The test fails with the old `checkout -B`.
