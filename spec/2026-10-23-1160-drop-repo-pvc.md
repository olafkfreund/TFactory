# Spec: drop the repo_pvc co-mount — packing is the only verify path

Owner decisions for #1160 step 5 (PR B), 2026-10-23. They are recorded here as
chosen; the alternatives are listed below as rejected.

## Design

### 1. Packing is the only verify path

- `tools/runners/kube_sandbox.py`
  - `build_job_manifest`: remove the `repo_pvc`, `repo_subpath` and `repo_ro`
    parameters and the `elif repo_pvc:` PVC volume branch. With
    `workspace_uri`, `workdir` is an emptyDir, as it is today. Without it, the
    Job mounts no workspace at all (toolchain-only). The `nix_store_pvc` mount
    stays, because it holds `/nix` and not the workspace.
  - `KubeJobSandbox`: remove `repo_pvc`, `_repo_kw` and the `pack_workdir`
    flag. A `run(..., workdir=...)` always packs that workdir (the #1391 lane
    path). A run with no workdir stays toolchain-only; the equivalence oracle
    and `k8s_job_target` use that and are unchanged.
  - `pvc_subpath` stays as the data-root-relative path helper that
    `verify_dispatch` uses to build the `/work` paths, with an updated
    docstring.
- `agents/nix_env.nix_runner_from_env`: stop reading `TFACTORY_WORKSPACES_PVC`
  and `TFACTORY_LANE_PACK`. `TFACTORY_DATA_ROOT` is still honoured for
  `data_root`.
- `agents/verify_dispatch.py`
  - `VerifyJobConfig`: drop `repo_pvc`; `workspace_uri: str` is required.
  - `build_verify_job_manifest`: stop passing `repo_pvc`/`repo_subpath`, and
    always set `WORKSPACE_ROOT`.
  - Job env: stop forwarding `TFACTORY_WORKSPACES_PVC`, and drop the
    `TFACTORY_LANE_PACK` / `TFACTORY_DATA_ROOT` entries. Nested lanes now
    always pack.
  - `dispatch_verify_job`: drop the `pack_workspace` parameter and always
    pack.
- `agents/equivalence_lane.py` and `agents/verify_workspace.py`: update only
  the docstrings that name the co-mount.

### 2. Remove the toggle

- `agents/gen_functional.py`: delete `_pack_workspace_enabled` and the
  `pack_workspace=` argument.
- If `TFACTORY_PACK_WORKSPACE` is set to any value, log one WARNING per
  process saying it is ignored (`functools.cache` on a small helper called at
  the dispatch site).
- Removing the variable from factory-gitops is a separate follow-up, and the PR
  says so.

### 3. Pack is not fail-open

**Dispatch level.** `pack_for_dispatch` returning `None` covers every failure:
no `S3_ENDPOINT`, nothing to pack, a pack error or an upload error. In that
case `dispatch_verify_job`:

- writes the queued row and then `mark_stuck(job_id, reason)`, where the reason
  starts `verify workspace pack failed (failure_kind=environment)`;
- writes the spec's `status.json` through the existing reaper writer
  (`_mark_spec_reaped`, extended with `phase` and extra fields):
  `status: failed`, `phase: verify_workspace_pack_failed`,
  `verify: not_run`, `failure_kind: environment`, and the reason. It then
  notifies terminal;
- applies no Job, and raises `VerifyWorkspacePackError`.

`gen_functional._run_dispatch_blocking` catches that one error and returns
`True`, so the verify is handled and the caller does **not** fall back to the
in-pod path. In-pod could produce a pass, and this outcome must never be a
pass. Every other dispatch fallback (no runner image, apply failure) is
unchanged.

At this level there are no per-AC verdicts yet, so the existing
`not_run`/environment vocabulary is carried on the run instead. The row is
`stuck` (`has_verdict` False), and `status.json` says `verify: not_run`,
`failure_kind: environment`.

**Lane level.** This uses the existing `__TF_LANE_NOT_COLLECTED__` →
`classify_pytest_failure` = `environment` → `apply_environment_override` →
`not_run` path.

- A lane pack/presign failure: `_run_async` returns a failed result. Its
  output already says `lane pack failed`, and it now also carries the marker.
- A lane input fetch failure: the wrapped command uses `set -o pipefail`
  around `curl | tar`, prints `[kube-sandbox] lane input fetch failed` and the
  marker, and exits non-zero. No push-back runs, so `_collected` also adds the
  marker.
- A lane push-back failure: unchanged. The result object is missing, so
  `_collected` returns failed with the marker.

### 4. Control-plane restore unchanged

`restore_packed_workspaces_once`, `restore_spec_from_workspace` and the in-Job
`restore_workspace`/`push_back_workspace` do not change.
`tools/runners/artifact_store.py` is vendored and gets no diff.

## Alternatives rejected

- **Keep the co-mount as a fallback for pack failures.** It silently re-pins
  verify to the PVC's node, which is the defect this issue removes.
- **Fall back to the in-pod verify on a pack failure.** It is still fail-open,
  and it can grade a pass on a run whose packed path is broken.
- **Keep `TFACTORY_PACK_WORKSPACE`, defaulting it to on.** A switch that can
  only bring back a removed path is a hazard; a one-time log covers stale
  config.
- **Fail hard on startup when the toggle is still set.** It would break the
  rollout while gitops still sets it to `true`.
- **Keep the `pack_workdir` flag on `KubeJobSandbox`.** With no PVC left, a
  workdir that is not packed would reach the lane empty, and that error is
  silent. Packing whenever a workdir is given removes that state.
- **Synthesize per-AC `not_run` verdicts on a dispatch pack failure.** It
  invents verdict rows for tests that were never staged. The row being `stuck`
  plus the `status.json` fields is honest and uses writers that already exist.

## Risks

- After the release, a verify with no object store (`S3_ENDPOINT` unset) is
  `failed`/`not_run` instead of co-mounted. On the factory cluster the store is
  present and the toggle is already on, so behaviour there does not change.
  Dev/test without a runner image never dispatches (`nix_runner_from_env`
  returns `None`).
- The in-pod verify path (`TFACTORY_VERIFY_EXEC` not `kubejob`) runs Nix lanes
  from the control plane. Those lanes now pack too, so they need `S3_*`, which
  the control plane has.
- Stale gitops variables (`TFACTORY_PACK_WORKSPACE`, `TFACTORY_WORKSPACES_PVC`)
  stay inert until the follow-up.

## Verification

- Unit (regression): no verify Job manifest and no nested lane manifest
  contains a `persistentVolumeClaim` volume other than the nix store. That
  holds even with `TFACTORY_WORKSPACES_PVC` set.
- Unit (regression): a dispatch whose pack returns `None` applies no Job,
  raises `VerifyWorkspacePackError`, marks the row stuck with
  `failure_kind=environment`, and writes `status.json` with `verify: not_run`.
  `_run_dispatch_blocking` returns `True` (no in-pod fallback).
- Unit (regression): `TFACTORY_PACK_WORKSPACE=false` is ignored: dispatch
  still packs, and the ignore warning is logged once.
- Unit: a lane pack failure and a lane input fetch failure both classify as
  `environment`.
- The full backend suite, `scripts/ratchet_lint.py --base origin/dev`, and
  `git diff origin/dev -- apps/backend/tools/runners/artifact_store.py` must
  be empty.
- On the cluster after the release, outside this PR: one packed run with no
  PVC on the verify or lane Jobs. #1160 closes then.
