# Spec: A shell lane (bats + shellcheck) and skip means not_run

## Design

Two parts: a lane (the Kotlin/Maven pattern) and a skip rule (the #1573 not-run
convention, exit 125).

### A. The shell lane

1. **Framework descriptor** `frameworks/bats/descriptor.yaml`: `language:
   shell`, `lanes: [unit]`, `source_extensions: [".sh", ".bash", ".bats"]`,
   `manifest_signals: []` (a shell project has no distinctive manifest, like
   portal-ui; detection is by extension and AC token),
   `ac_command_tokens: ["bats tests", "bats test/", "shellcheck"]`,
   `test_path_conventions: ["tests/**/*.bats", "test/**/*.bats",
   "**/tests/**/*.bats"]`, `coverage_strategy: skip`, nominal runtime image.
   Planner validator then accepts (shell, bats, unit) and the Planner emits
   `.bats` files instead of pytest wrappers.
2. **Toolchain descriptor** `apps/backend/tools/runners/languages/shell.yaml`
   (aliases bash, sh, shell; `nix.packages: [bats, shellcheck]`; unit lane
   tool bats; mutation, browser, api, integration `available: false` with
   reasons). `generate_flake` fails closed for an unknown language, and
   descriptor-declared languages are the paved road (language_descriptors.py).
   The vendored hub files stay byte-exact; this is a TFactory-only addition
   (the drift gate registers named files; follow-up: promote to the hub).
3. **Lane runner** in a new module `agents/nix_shell_lane.py`:
   `shell_environment(spec_dir, project_dir)`: when the repo owns a flake
   (`flake_is_repo_owned`) the manifest is `provisioning.generated: false`, so
   `materialize_flake` respects it and bats/shellcheck must come from the
   project's own `devShells.default` ("inside the project's nix develop");
   otherwise a generated flake from the descriptor. `bats_job_script` (pure):
   each of `bats` and `shellcheck` checked with its own `command -v` (a
   chained call passes when only the last exists); either missing -> `__BATS_EXIT=126` (not run, with a
   message naming what is absent); else `bats --tap` over every `*.bats`
   (excluding .git), `BATS_TMPDIR=/tmp`, then `shellcheck -x -S warning` over
   `*.sh`/`*.bash` outside tests; markers `__BATS_EXIT`, `__SHELLCHECK_EXIT`.
4. **TAP parser and verdict** `parse_tap(text) -> (passed, failed, skipped)`
   (`ok N`, `not ok N`, `ok N ... # skip`). `shell_verdict`: failed > 0 or
   bats non-zero -> 1; shellcheck findings (exit 1) -> 1 with stderr
   "shellcheck reported findings"; zero tests -> 1 ("bats ran zero tests");
   only skipped (passed = 0, skipped > 0) -> 125; marker 126/127 kept (not
   run). Any failure beats any skip.
   Tool errors: the exit marker missing, bats exit other than 0/1, or
   shellcheck exit other than 0/1 (2+ = usage/tool error) are 1 even if the
   other tool passed; a pass requires BOTH markers present and clean.
5. **Evaluator wiring** as for Rust: `_completed_shell_subtasks` (language
   shell), `_resolve_shell_runner_fn`, `shell` branch in `_build_all_bundles`
   (stage files, one stability pass per project root), `mutation=None`.

### B. Skip is not_run in the pytest lane

`agents/stability_runner.py` (home of `_SHELL_NOT_RUN_CODES`) gets one pure
helper `all_skipped(text)`: pytest summary shows
`N skipped` and none of passed/failed/error/xfailed/xpassed. It is applied
where an exit code 0 is read from a pytest run: `parse_pytest_exits` (batched
stability, per-run body), `parse_mut_exits` (batched mutants; now reads each
mutant's body), `_parse_pytest_exit` (single run), and the evaluator's host and Docker
runners through `_parse_marker_exit` (evaluator.py:478, 631), the reachable
fallbacks. An all-skipped zero
becomes 125. Downstream already routes 125: mutation NOT_RUN
(`_mutation_from_codes`, `_SHELL_NOT_RUN_CODES`), stability failure_kind
"environment", verdict reclassified `not_run` (confidence.py:
`apply_environment_override`). A mixed run (some passed) is untouched.

### C. Docs: capabilities row, shell section in framework-registry.md with the
`verify_commands` fallback and its limit.

## Alternatives rejected

- Promote shell to the Factory hub now: a cross-repo, drift-gate change in a
  round where many teams touch the hub; deferred as a follow-up.
- Fail the generated pytest wrapper at the source (strip `pytest.skip`):
  fixes one generator habit; the exit-0 skip would still read as a pass for any
  skipped test.
- Teach `classify_stability_runs` about skips: needs per-run bodies it does not
  have; the exit-code convention already exists.
- Make nix a runner prerequisite: the lane's whole point is that the Nix shell
  provides the tools.

## Risks

- `shellcheck` findings in pre-existing scripts fail the whole lane (module
  wide, as for Go); documented, severity limited to warning and above.
- A repo flake lacking bats/shellcheck in its devShell yields not_run (126),
  with a message, never a pass.
- The pytest skip rule changes verdicts for any all-skipped pytest run, which
  is the intended fix; tests that legitimately skip everything become
  not_run, never accept.
- Merge conflicts with the Rust PR (evaluator.py, docs): mechanical.

## Verification

Unit tests: descriptor + toolchain descriptor load; validator accepts shell
subtasks; TAP fixtures (all ok, one not ok, all skip, mixed skip+fail, zero);
job script has the not-run guard and checks each tool; tool-error precedence;
existing tests updated (`test_planner_language_vocabulary` extension map,
`test_lang_registry` unit-language sets); `_all_skipped` table incl. mixed; the three
parsers map all-skipped to 125 and leave a normal pass at 0; end-to-end
`_mutation_from_codes` NOT_RUN; evaluator routing; fails closed when sandbox
unset. No live cluster run in this round.
