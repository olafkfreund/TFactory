# Spec: TFactory UI test fixes

## Design

- **B1.** `apps/web-server/server/routes/context.py:429-431`: GET `/env`
  moves to `ProjectAccessChecker("viewer")`. For callers below admin,
  secret-valued fields are blanked and the `*Set` booleans kept, as in
  PFactory. PATCH stays admin.
- **B7.**
  - `TFactoryPortal` takes an optional `projectId` and filters its
    pipeline and runs to that project.
  - In `App.tsx`, the `activeView === 'tfactory'` branch (`:488-497`)
    renders `<TFactoryPortal projectId=...>` instead of the placeholder
    list.
  - `setActiveView` (`:150-153`) no longer navigates to `/tests` for
    `tfactory` when a project is selected; unscoped `/tests` stays as the
    all-projects view.
- **B8.** `routes/projects.py:331-339` adds `slug` to the response, using
  the stored slug or the `project-route.ts` derivation moved server-side.
  A cloned project defaults its name to the repo name (`:697`).
- **B15.** In the pipeline view, runs whose status is a terminal failure
  (`*_failed`) are removed from the stage columns and counted behind a
  "Failed (N)" toggle that lists them. Each failed item offers "Re-run",
  the existing rerun or `task_rerun` route, and "Dismiss", the existing
  `dismiss_run` route. Dismissed runs disappear.
- **B4, B10, B17:**
  - the version from `/api/health`;
  - Add Project defaults to clone with no scan on open;
  - Recent Projects shows the repo or name, not the pod path.

## Alternatives rejected

- **A new failed lane in the backend:** the status already marks failure;
  this is view logic.
- **Deleting failed runs:** history must stay reachable.

## Risks

- The B7 project filter must match task-to-project mapping by both
  workspace id and project id.
- B15 must not hide a run that is being retried.

## Verification

- Route tests for B1 and B8.
- vitest for B7 (navigation keeps the project), B15 (failed runs filtered,
  re-run and dismiss call the right routes), B4 and B10.
- CI.
- After release, a browser re-test:
  - open project, then Tests, stays scoped;
  - the MCP view without 403;
  - failed runs are behind the filter;
  - the version is correct.
