# Spec: TFactory UI test fixes

## Design

- **B1.** `GET /env` (`routes/context.py:429-433`) moves to viewer. The
  handler gets the effective `ProjectAccess` from `require_project_role`
  (`request` plus `db`), so the token scope ceiling applies.
  - Below admin, it returns an **explicit allowlist**: git
    provider/repo/org/project, `gitBaseUrl` with userinfo stripped, the
    `*Set` / `*Enabled` booleans (plus a new `graphitiKeysSet`), and the
    MCP booleans.
  - Never returned below admin: `gitToken` and the four
    `graphitiProviderConfig.*ApiKey` values.
  - Admin and owner get the full payload. PATCH stays admin.
  - `tests/test_project_authz_route_table.py` (`test_sensitive_route_dependency_roles`)
    is updated to viewer for GET.
- **B7.**
  - `GET /api/tfactory/tasks` accepts an optional `project_id` and
    filters server-side. The match uses the resolved registry id for each
    workspace, so a UUID or a workspace name both work.
  - `TFactoryPortal` gets an optional `projectId`, which flows to
    `TFactoryPipelineView` and the board.
  - Selection becomes project-qualified (`{projectId, specId}`) through
    detail, logs, artifacts, merge, dismiss and rerun, and the HTTP calls
    pass `?project_id=`. The WebSocket log handler accepts `project_id`.
  - Changing the project resets the detail view (`key` on the project).
  - `App.tsx:488-497` renders the scoped portal in place of the placeholder
    list. `setActiveView` (`:150-153`) keeps the project, and `/tests`
    stays the global view.
  - `handleTaskClick` is removed if it becomes unused.
  - `project-routing.test.tsx` is updated, and a real Tests click from
    another view is tested.
- **B8.**
  - The project response gains `slug`, a base slug from the stored name.
    The client keeps its collision and alias handling (`project-route.ts`).
  - New clones and ingest self-registrations default the display name to
    the repo basename (`.git` stripped). An explicit name always wins.
  - Existing records are unchanged.
- **B15.**
  - **Rerun route:** `POST /api/tfactory/tasks/{spec_id}/rerun?project_id=`
    (member, D6 404s). It refuses with 409 while the run is active or
    already re-running, calls `rerun_pipeline`, clears `dismissed`, and
    returns `planner_scheduled` and `planner_reason`.
  - **Summary:** `_summary_row` exposes `dismissed`.
  - **Board:** runs where `isFailed(t)` is true (`*_failed`, `failed`,
    `stuck`, `stalled`, `replan_needed`) leave the stage columns for a
    "Failed (N)" toggle. Dismissed runs are hidden unless "Show dismissed"
    is on. Each item offers Re-run and Dismiss. When the planner is not
    scheduled, the UI shows its reason.
  - `TFactoryPipelineBoard.test.tsx` is updated.
- **B4.** A cached `/api/health` version for Settings and Debug, with
  "unknown" on failure and no unhandled rejection.
- **B10.** `AddProjectModal.tsx:54,100-115`: the default is clone with no
  scan on open, the state resets on open only, and Local scans on choice.
- **B17.** The project response gains `repoLabel`, a sanitized
  `owner/repo` from `clonedFrom` with no userinfo. `WelcomeScreen.tsx:109-111`
  and `ProjectsPage.tsx:46-48` show it instead of the pod path.
- **i18n:** every new label goes into `en`, `fr` and `pt-BR`.

## Alternatives rejected

- **A new failed lane in the backend:** the status already marks failure;
  this is view logic.
- **Deleting failed runs:** history must stay reachable.

## Risks

- The B7 project filter must match task-to-project mapping by both
  workspace id and project id.
- B15 must not hide a run that is being retried.

## Verification

- Route tests for B1 and B8.
- vitest for B7 (navigation keeps the project), B15 (failed runs filtered,
  re-run and dismiss call the right routes), B4 and B10.
- CI.
- After release, a browser re-test:
  - open project, then Tests, stays scoped;
  - the MCP view without 403;
  - failed runs are behind the filter;
  - the version is correct.
