# Spec: the handback sender authenticates to AIFactory

## Design

Mirror PFactory#930 in `apps/backend/agents/handback/send.py`:

- `_auth_headers(api_url) -> dict[str, str]` returns
  `{"Authorization": f"Bearer {token}"}` only when a token is set and `api_url`
  has the same `(scheme, netloc)` as `workspaces.snapshotter._default_api_url()`
  (`TFACTORY_AIFACTORY_API_URL`, default `http://localhost:3101`). Otherwise `{}`.
  `api_url` is read back from `source.json` on disk, so the origin check keeps
  the token off any other host.
- Token: `APP_API_TOKEN`. TFactory makes no other AIFactory call, so there is
  no existing AIFactory token chain to reuse; `APP_API_TOKEN` is the shared
  credential the TFactory pod already mounts from `factory-secrets` (the same
  secret AIFactory reads). PFactory's chain names PFactory-only variables.
- `default_sender` merges the helper into the request headers. The SSRF guard
  stays; the comment that says no credential rides on the request is updated.
- The token is never logged.

## Alternatives rejected

- A new `TFACTORY_AIFACTORY_API_TOKEN`: the task forbids a new variable, and gitops does not set one.
- Reusing `TFACTORY_MCP_KEY` / `~/.tfactory/.token` (`tools_pkg/http_client.py`): those are TFactory's own tokens, not AIFactory's.
- Sending the token to any `api_url`: `source.json` is on disk; a rewritten URL would leak it.

## Risks

- If `TFACTORY_AIFACTORY_API_URL` differs in form from the snapshotted `api_url` (for example a host alias), no header is sent and the send still fails 401, as today. Sending stays off by default.

## Verification

`tests/test_handback_send.py` covers token set → header sent; no token → no
header; foreign origin → no header. The first case fails on `origin/dev`.
