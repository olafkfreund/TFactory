# Spec: say why the SUT/sidecar was unhealthy

## Design

All in `agents/nix_env.py`, pytest-lane Job script and its warning:

1. Serve prelude: capture `TF_SUT_PID=$!`; readiness loop becomes an elapsed-time deadline
   (`end=$((SECONDS+60))`, matches the sidecar wait), each probe, including the
   final check, `curl --connect-timeout 2 --max-time 3` (still no `-f`, so 404 is
   up), and breaks early when `kill -0 "$TF_SUT_PID"` fails (SUT died). A serve
   command that daemonizes is out of scope (same as today).
2. On failure the Job prints the existing marker line extended with the SUT state
   (`exited` / `still running, not accepting connections`) followed by
   `__TF_APP_LOG_BEGIN__`, `tail -n 20 /tmp/tf_app.log`, `__TF_APP_LOG_END__`.
   The sidecar probe message already names the failed probe; it is kept.
3. New pure helper `_unhealthy_reason(stdout)` returns the marker lines plus the
   app-log block (capped). `run_pytest_lane_via_nix` logs it in the warning
   (instead of `stdout[-300:]`) and appends it, capped to fit the 500-char stdout
   tail, before the final marker so lane output carries the reason.
4. No change to the generated flake, sidecar manifest or verdict classification.
   Root cause for factory-lab-cloud PR #1 cannot be read (Job TTL expired); the
   next run names it. Sidecar container logs are a follow-up (sandbox reads only
   the `lane` container).

## Alternatives rejected

- Dump `/tmp/tf_app.log` as an artifact: needs sandbox plumbing; stdout is enough.
- Guess-fix the generated env (extra packages, pre-start order): unverifiable
  without the failing log.

## Risks

App log tail may contain app output; it is the SUT's own stdout from a throwaway
Job, already visible today in test output. Cap keeps lane output small.

## Verification

Unit tests on the generated script (PID capture, early exit, bounded curl, log
block present only on failure path), `_unhealthy_reason` extraction/cap, and a
real-layout test (`app/requirements.txt` with psycopg[binary]+redis, `app/main.py`)
asserting both sidecars, DATABASE_URL/REDIS_URL exports before the serve prelude,
and the reason reaching the returned stdout. Existing tests for #612/#1582 pass.
