# Spec: A Rust unit lane (cargo test)

## Design

Mirror the Maven lane (#1321), which needed no hub descriptor because the
provisioner already owns the toolchain: `nix_provisioner._LANG_ATTRS["rust"]`
is `[rustc, cargo]` (apps/backend/tools/runners/nix_provisioner.py:474).

1. **Framework descriptor** `frameworks/cargo-test/descriptor.yaml`: `language:
   rust`, `lanes: [unit]`, `source_extensions: [".rs"]`, `manifest_signals:
   ["Cargo.toml"]`, `ac_command_tokens: ["cargo test", "cargo build"]`,
   `test_path_conventions: ["tests/*.rs", "**/tests/*.rs"]` (top-level files only:
   each is an integration-test target Cargo runs automatically; a nested
   `tests/helpers/x.rs` is an unreferenced module Cargo never executes),
   `coverage_strategy: skip` (no coverage is collected), nominal
   `runtime.image: tfactory-runner-rust:latest` (as Gradle/Maven: the lane runs
   as a Nix Job). The Planner validator then accepts (rust, cargo-test, unit).
   Integration tests under `tests/` are the only generated form: inline
   `#[cfg(test)]` modules would mean editing the SUT, which Gen-Functional never does.
2. **Prompt fallback removal**: `.rs` and the `cargo test`/`cargo build` tokens
   leave `_NO_DESCRIPTOR_EXT_LANGUAGE` / `_NO_DESCRIPTOR_AC_COMMANDS` in
   prompts.py (they are now derived; the existing test forbids declaring both).
   The derived table is byte-identical for Rust.
3. **Lane runner** in a new module `agents/nix_rust_lane.py` (keeps nix_env.py,
   a conflict hotspot, untouched): `rust_environment(spec_dir)` (contract env if
   it declares rust, else `{language: rust, verify_commands: ["cargo test"],
   network: restricted, generated}`), `_cargo_crate_dir` (nearest `Cargo.toml`
   at/above the hint, else shallowest; workspace root preferred), pure
   `cargo_job_script` and `run_cargo_lane_via_nix`. The Job copies the crate to
   a writable dir (the worktree is read-only to the Job uid), sets
   `CARGO_HOME` and `CARGO_TARGET_DIR` under `/tmp`, runs `cargo test
   --workspace --no-fail-fast 2>&1` (explicit `--workspace`: at a workspace root
   plain `cargo test` runs only default members), and emits `__CARGO_EXIT=<code>`.
4. **Parser and evidence rule** `parse_cargo_test_output(text) -> CargoCounts`
   sums every `test result: <ok|FAILED>. N passed; F failed; I ignored;`
   line (unit binaries, integration binaries, doc-tests). Verdict: cargo exit
   non-zero is kept as is; exit 0 with zero tests run is converted to 1 ("cargo
   ran zero tests"); exit 0 with only ignored tests is 125 (not run); failures
   with exit 0 cannot happen but are 1 for safety. Same shape as the Gradle
   evidence rule.
5. **Evaluator wiring**: `_completed_rust_subtasks` (unit/functional + rust),
   `_resolve_rust_runner_fn`, a `rust` branch in `_build_all_bundles` that
   stages test files with `_stage_go_test` and shares one 3x stability pass per
   crate (the `_jvm_bundles` approach, resolver `_cargo_crate_dir`), bundles
   with `mutation=None`, and per-target attribution: `cargo_ran_targets(text)`
   reads the `Running tests/<name>.rs` lines; a subtask whose file is absent
   gets a stability ERROR so aggregate counts from other tests cannot vouch for
   it (the `_per_class_stability` precedent). `completed = ... + rust_completed`.
6. **lang_registry**: static row `rust.unit = ToolSpec("cargo", "cargo test ...")`;
   other cells stay `None` (test_lang_registry expectation updated).
7. **Docs**: capabilities table row, a Rust section in framework-registry.md
   including the manifest `verify_commands` fallback and its limit.

## Alternatives rejected

- Adding `languages/rust.yaml`: `_LANG_ATTRS` already owns rust and the
  descriptor path returns None for such languages (nix_provisioner.py:504).
- cargo-nextest / cargo2junit for JUnit XML: extra packages and a new
  dependency to avoid a 15-line text parse.
- Editing nix_env.py: it is a shared hotspot; a sibling module is the smaller
  conflict surface and keeps Go/JVM lanes untouched.
- Wiring the existing `lang_rust` mutation probe now: it writes the mutant
  outside the crate and uses a two-argument runner; out of scope (intent).

## Risks

- Cold crate downloads can exceed the timeout: 900 s like Maven; egress is
  admitted by the build-Job policy (Maven measured; crates.io unmeasured:
  stated as unverified in the PR).
- A multi-crate repo: one pass per crate root, graded as a module (like Go).
- Merge conflicts with the shell-lane PR in evaluator.py signatures/docs;
  mechanical, resolved by rebase.

## Verification

Unit tests: descriptor loads and validates; Planner validator accepts a
(rust, cargo-test, unit) subtask and rejects a wrong path; prompt tables
unchanged for Rust; cargo output parser fixtures (ok, failed, zero tests,
all ignored, multi-binary, doc-tests); job script content; runner fails closed
when the sandbox is unset; evaluator routes only Rust subtasks to the lane and
a Rust-only plan is not `evaluated_empty`; a subtask whose `tests/<name>.rs`
target does not appear in cargo's `Running tests/<name>.rs` lines gets a
stability ERROR ("this test did not run"), like the JVM per-class check. No live cluster run in this round.
