# Spec: presign lane URLs with SigV4

## Cause (confirmed)

botocore 1.43 reports `signature_version = s3v4` for the client, yet
`generate_presigned_url` without an explicit `signature_version` falls back to
legacy SigV2 query auth (`AWSAccessKeyId`, `Expires`, `Signature`, with
`x-amz-tagging` in the query, no `X-Amz-SignedHeaders`). Reproduced against a
local MinIO container with the exact presign from `_pack_lane` and the exact
`curl -fsS -T` the lane script runs: `403 SignatureDoesNotMatch`.

## Design

Chosen (user decision for this wave: smallest change that makes the round-trip
succeed): construct the `ArtifactStore` boto3 client with
`botocore.config.Config(signature_version="s3v4")`
(`apps/backend/tools/runners/artifact_store.py` `_client`). Presigned URLs
become SigV4 with `x-amz-tagging` in `X-Amz-SignedHeaders`; the URL no longer
contains `x-amz-tagging=`, so the existing lane-script branch in
`kube_sandbox._pack_lane` sends `-H 'x-amz-tagging: role=workspace'`, which
MinIO verifies and applies as the lifecycle tag. Plain `put_object` calls
already used SigV4, so that path is unchanged. No change to `kube_sandbox.py`.

## Alternatives rejected

- Drop `Tagging` from the presign and `put_object_tagging` after collection:
  more code, and an out object left untagged if collection never happens.
- A separate SigV4 client only for presigning: a second client for no gain,
  since explicit s3v4 changes nothing on non-presigned calls.

## Risks

- SigV4 presigned URLs cap `ExpiresIn` at 7 days; lane URLs are timeout+600s.
- Any other presign caller now gets SigV4 too (none rely on SigV2).

## Verification

- Unit test: presigned PUT URL is `AWS4-HMAC-SHA256`, signs `x-amz-tagging`,
  and has no `x-amz-tagging=` in the query (fails on SigV2).
- MinIO round-trip test, skipped unless `TF_TEST_MINIO_ENDPOINT` is set:
  `_pack_lane` → curl -T as the script does → `collect()` → junit present and
  tag `role=workspace` on the object. Fails with 403 without the fix.
