# Spec: presign lane URLs with SigV4

## Cause (confirmed)

botocore 1.43 reports `signature_version = s3v4` for the client, yet
`generate_presigned_url` without an explicit `signature_version` falls back to
legacy SigV2 query auth (`AWSAccessKeyId`, `Expires`, `Signature`, with
`x-amz-tagging` in the query, no `X-Amz-SignedHeaders`). Reproduced against a
local MinIO container with the exact presign from `_pack_lane` and the exact
`curl -fsS -T` the lane script runs: `403 SignatureDoesNotMatch`.

## Design

Chosen (user decision for this wave: smallest change that makes the round-trip
succeed): presign the lane URLs with a boto3 client built with
`botocore.config.Config(signature_version="s3v4")`, created by
`_presign_client(store)` in `apps/backend/tools/runners/kube_sandbox.py` from the
store's `StoreConfig` (revised in fix round 1, see below). Presigned URLs
become SigV4 with `x-amz-tagging` in `X-Amz-SignedHeaders`; the URL no longer
contains `x-amz-tagging=`, so the existing lane-script branch in
`kube_sandbox._pack_lane` sends `-H 'x-amz-tagging: role=workspace'`, which
MinIO verifies and applies as the lifecycle tag. Uploads and deletes still
go through `store._client()`, which is unchanged.

Revision (fix round 1, PR #1398 review): `artifact_store.py` is a byte-exact
vendored copy of the Factory hub's `scripts/artifact_store.py`, enforced by the
"vendored copies match the hub canonical" CI gate, so it cannot be edited here.
The s3v4 config therefore lives in `kube_sandbox.py`, which is not vendored.
Making every consumer's presigns SigV4 via the hub canonical is a separate,
hub-first change (follow-up), not part of this fix.

## Alternatives rejected

- Drop `Tagging` from the presign and `put_object_tagging` after collection:
  more code, and an out object left untagged if collection never happens.
- Set s3v4 on the `ArtifactStore` client in `artifact_store.py`: the original
  choice, rejected in fix round 1 because the file is vendored from the hub and
  the drift gate forbids local edits. Doing it hub-first (canonical PR,
  re-vendor into every consumer, bump `HUB_PIN_SHA`) is a larger cross-repo change.

## Risks

- SigV4 presigned URLs cap `ExpiresIn` at 7 days; lane URLs are timeout+600s.
- A second boto3 client per packed lane (cheap, no network at construction).
- Other `ArtifactStore` presign callers stay SigV2 until the hub canonical changes.

## Verification

- Unit test: presigned PUT URL is `AWS4-HMAC-SHA256`, signs `x-amz-tagging`,
  and has no `x-amz-tagging=` in the query (fails on SigV2).
- MinIO round-trip test, skipped unless `TF_TEST_MINIO_ENDPOINT` is set:
  `_pack_lane` → curl -T as the script does → `collect()` → junit present and
  tag `role=workspace` on the object. Fails with 403 without the fix.
