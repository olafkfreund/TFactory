# Spec: shell lane per-file isolation

## Design

1. `frameworks/bats/descriptor.yaml` context_block: forbid `nix` invocations and
   network use in tests; assert flake/nix files statically (grep) instead.
2. `bats_job_script`: loop over the .bats files, run `bats --tap "$f"` each,
   print `__BATS_FILE_EXIT=<rc> <path>` after each file, and report
   `__BATS_EXIT` as the worst code. Lane-wide verdict is unchanged.
3. `nix_shell_lane`: `file_results(stdout)` splits the FULL stdout at those
   markers and grades each file with `shell_verdict` (0 pass, 1 fail, 125 all
   skipped). `run_bats_lane_via_nix` appends the full TAP counts and failing
   files to the reason (stderr), which is short and never clipped away.
4. `evaluator._resolve_shell_runner_fn` records, per run and BEFORE any
   clipping, the per-file results and whether shellcheck passed.
   `_shell_bundles` then grades each subtask from its own file's result
   (`_per_file_stability`, same shape as `_per_class_stability`), with
   file-specific evidence. A run where shellcheck did not pass (or tools were
   unavailable) keeps the shared result for every subtask; a subtask whose
   file has no result is ERROR ("did not run"), never a pass.

## Alternatives rejected

- One bats Job per subtask: 3x runs each pays nix shell entry per file.
- Marking nix tests skipped: a skip is not_run, which costs the same VAL level.
- Raising the 4000 clip: the cost moves into verdicts.json for every lane.

## Risks

The recorded per-run results live in the runner closure; if the runner is replaced
by one without them the shared result is used (today's behavior).

## Verification

Unit tests for `file_results`, the job script, reason counts and
`_per_file_stability` (one failing file, others stable; shellcheck failure fails all;
missing file result is ERROR; long output). They fail without the change. `scripts/ratchet_lint.py` for
apps/backend and apps/web-server; ruff.
