# Spec: cookie fallback for WebSocket auth

## Design
- **Token order in `_ws_extract_token`:** first the `Authorization: Bearer` header, then `?token=` (deprecated), then the `access_token` cookie.
- **Origin check on the cookie path only.** The cookie is accepted only when the `Origin` header is present and same-origin: its host equals the request host, or it is in the server's configured allowed origins (reuse the CORS settings).
- **Missing or foreign Origin** with only a cookie: close with 4001.
- **`TFactoryLogViewer`:** 4001 and 4003 are terminal. Set the error state and show "Not authorised: sign in again". No reconnect.

## Alternatives rejected
A short-lived WS ticket endpoint. It is more code; the cookie with an Origin check is the standard same-origin pattern.

## Risks
CSWSH if the Origin check is wrong. Tests cover a foreign Origin, a missing Origin and a same Origin.

## Verification
- Unit tests for the token order and the Origin rules.
- A viewer test for 4001.
- Live: Logs connects for an SSO session.
