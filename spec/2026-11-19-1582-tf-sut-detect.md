# Spec: Sidecars and self-served SUT for contract-less api specs

## Design

nix_env.py: `api_services_fallback_env(spec, project, lane)` returns a minimal generated nix manifest when lane == api and required_services() is non-empty. `run_pytest_lane_via_nix` passes it as materialize_flake fallback_env; evaluator `_nix_verify_mode(spec, project, lane)` accepts it, and `_maybe_nix_verify`, the batched stability check and `_maybe_self_serve_api_bundle` pass the lane (the host self-serve must be skipped or it would start the SUT on the host). Alternatives rejected: making every python spec nix (cost and blast radius); host sidecars (no isolation).

## Alternatives rejected

See Design.

## Risks

Unit-lane specs are unchanged (lane gate). A repo-owned flake still wins (generated=True). The generated minimum relies on pip-installing the SUT deps from requirements, as the existing nix path does.

## Verification

Unit tests built on the real layout that fail on origin/dev and pass with the change; ratchet_lint for apps/backend and apps/web-server; live re-verify after release 0.13.1 (owner/coordinator).
