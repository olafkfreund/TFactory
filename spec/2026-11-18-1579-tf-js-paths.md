# Spec: Planner must not plan .ts tests for a JavaScript-only repo

## Design

Add _normalise_js_test_paths in apps/backend/agents/planner.py, run in _validate_emitted_plan before the checks: in a plain-JS project, for frameworks with a .js convention, rewrite .ts/.tsx to .js/.jsx and save test_plan.json. Strengthen the invalid_test_path retry reminder. The existing rejection stays as a safety net. A rerun re-plans through the same path, so it is normalised too.

## Alternatives rejected

Only strengthening the retry prompt: still model-dependent, the rerun repeated the failure.

## Risks

A framework whose JS convention differs in stem from the .ts one would still be rejected by the convention check, as before.

## Verification

tests/test_planner.py: JS-only fixture with .ts plan is accepted first time and saved as .js.
