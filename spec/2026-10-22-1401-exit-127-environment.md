# Spec: a lane exiting 126/127 is graded reject instead of not_run

## Design

User's decision (chosen): in `classify_pytest_failure`
(`apps/backend/agents/stability_runner.py`), right after the environment
marker check and before the import/assertion checks, return
`"environment"` when `returncode in (126, 127)`. pytest never exits
126/127; only the shell does, so the test never ran. This is the single
shared classifier: every lane (pytest, jest, browser via the
`__*_EXIT` markers, go/gradle/maven via `StabilityRun.returncode`) reaches
it through `StabilityResult.failure_kind`, so no per-lane change is needed.
`app_not_healthy` still takes precedence.

Change the `not_run` reason in `apply_environment_override`
(`apps/backend/agents/confidence.py`) from "the lane had no target URL ..."
to a generic "the lane's environment was unusable — the test never ran
(infra not_run, not an acceptance failure)".

## Alternatives rejected

- Match the text "command not found": prose inference, the defect class #1344
  forbids; also locale-dependent.
- A per-lane check in each jest/go/gradle/maven runner: duplicates one rule in
  several places when they all already share the classifier.

## Risks

A test runner that itself exits 126/127 would be relabelled not_run. None of
pytest, jest, go test, gradle or maven use those codes, so the risk is an
under-claim (not_run) rather than a false reject.

## Verification

- `classify_pytest_failure("...python: command not found", 127) == "environment"`, same for 126.
- Three `StabilityRun(returncode=127)` -> `failure_kind == "environment"` ->
  `apply_environment_override` relabels a reject to `not_run`.
- Exit 1 with `assert` text stays `"assertion"`.
- ruff, `scripts/ratchet_lint.py`, targeted pytest green.
