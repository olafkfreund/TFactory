# Spec: Task status for spec-ingest ids

## Design

`_ingest_path` in apps/web-server/server/routes/execution.py: a bare id is searched in `<workspace_root>/workspaces/*/specs/<spec>/status.json` (delete_task layout) and answers only when exactly one REGISTERED project's workspace matches (unregistered or ambiguous: nothing is revealed); `name:spec` resolves the name to the project uuid. `_status_access` authorizes against that uuid (Codex review: name ids were authorized by name, unregistered owners leaked, newest-wins raced) Alternative rejected: Postgres job-state lookup (owner decision on the issue: status.json covers inline stages).

## Alternatives rejected

See Design.

## Risks

Bare ids are looked up across workspaces but only a unique registered-project match answers. The MCP proxy route has no project check for bare ids (parity with its other task routes); only the project-prefixed form is RBAC-checked there.

## Verification

Unit tests built on the real layout that fail on origin/dev and pass with the change; ratchet_lint for apps/backend and apps/web-server; live re-verify after release 0.13.1 (owner/coordinator).
