# Spec: Run a vitest subpackage with its own runner

## Design

In run_jest_lane_via_nix (the single JS/TS unit-lane runner), after the test is staged, walk up from its path to the nearest package.json. If it lists vitest in dependencies or devDependencies, replace the jest setup/run with: cd <pkg>; npm ci (package-lock.json present) or npm install; check node_modules/.bin/vitest; run vitest run <file>. Otherwise unchanged. Same exit markers so rerun batching and stability parsing are untouched.

## Alternatives rejected

Add vitest to the root jest install: wrong for subpackages with their own deps. Detect in discovery.py: that path is not on the lane's execution route. pnpm/yarn lockfile support: deferred (falls back to npm install; marked shortcut in code).

## Risks

A package that declares vitest but whose generated test uses jest globals fails under vitest: acceptable, the package's declared runner is authoritative. Install needs network in the sandbox, as the existing jest install already does.

## Verification

tests/test_jest_lane_staging.py: vitest subpackage gets npm ci + vitest run and no jest; far package.json is ignored. Existing jest tests still pass.
