# Intent: the handback sender authenticates to AIFactory

## Problem

`apps/backend/agents/handback/send.py::default_sender` posts to AIFactory's
`POST /api/tasks/{task_id}/apply-correction` with only `Content-Type`. The route
needs `require_task_access("member")`, so once `TFACTORY_HANDBACK_SEND` is on,
every send fails with 401/403. It is latent: sending is off by default.

## Proposed outcome

With sending on and a token configured, the POST carries
`Authorization: Bearer <token>` to the configured AIFactory origin and nowhere
else. Same shape as PFactory#930.

## Affected users and systems

TFactory backend (handback sender), AIFactory's apply-correction route.
No deployment change: the pod already mounts `APP_API_TOKEN`.

## Constraints

- Keep the SSRF guard (#1117).
- The token never leaves the configured AIFactory origin and is never logged.
- No new environment variable.

## Open questions

None.
