# Intent: A task with completed subtasks never ends as a quiet evaluated_empty

## Problem

A level-5 Java spec-ingest task (olafkfreund/factory-lab-java, Maven, JUnit 5)
generated 13 test files and marked all 13 subtasks `completed`
(`language: java, framework: junit, lane: unit`), spent 15.34 USD, and ended as
`evaluated_empty` / `evaluator_no_completed_subtasks`, `verdicts: []`, Triager
never run. Copying the files into the module and running `mvn test` passes, so
the tests are runnable.

Checked against current `dev`: `_completed_java_subtasks` (evaluator.py, #1321)
admits exactly these subtasks and the real `test_plan.json` of that run yields
13 java subtasks through it. The MCP server that ran the task executes a stale
checkout (`/mnt/code/Source-home/GitHub/TFactory` at v0.9.25-386, Aug 2026),
which has no Java lane at all, so every subtask was dropped. The remaining hole
on `dev` is the same shape: a completed subtask whose (language, lane) no lane
filter admits is dropped silently and the run ends `evaluated_empty`, which
`verify_pipeline` and #1263 call infra, not a verdict.

## Proposed outcome

If the plan holds completed subtasks with test files but no evaluator lane
admits any of them, the evaluator ends `evaluator_failed` with a reason naming
the unadmitted (language, framework, lane) tuples. `evaluated_empty` stays only
for plans that truly have nothing completed.

## Affected users and systems

TFactory evaluator (`apps/backend/agents/evaluator.py`), in-pod and kubejob
verify; operators reading task status.

## Constraints

Do not redo #1573 or the Java lane (#1321/#1356). No new image path. The stale
checkout of the running MCP server is an operator action, not code.

## Open questions

None. Decision (owner delegation 2026-11-18): fail closed with `evaluator_failed`,
consistent with the existing unsupported-language branch and tf-sandbox's rule.
