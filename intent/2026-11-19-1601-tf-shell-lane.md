# Intent: shell lane survives sandbox-hostile tests and reports full counts

## Problem

On factory-lab-shell PR #1 the shell lane (#1581) generated `test/flake.bats`
tests that run `nix flake show`. The sandbox has no network and no nix daemon,
so they fail. The lane runs one shared `bats` over all files, so that one file
made bats exit 1 and every generated test (6) was rejected: VAL-0 after 10 USD
and two attempts. The per-run output kept as evidence is clipped to its last
4000 chars, so the pass/fail counts a reader sees are lower bounds.

## Proposed outcome

- The generator is told not to emit tests that need nix or network.
- A failing .bats file rejects only its own subtask; the others are graded on
  their own results.
- Full TAP counts and the per-file results survive the 4000-char clip.

## Affected users and systems

TFactory shell lane (`nix_shell_lane.py`, `evaluator.py`), the `bats` framework
prompt block. Shell-project verifications.

## Constraints

Shellcheck findings and tool errors still fail the whole lane. A skipped-only
file stays not_run. No new dependencies; no change to other languages' lanes.
