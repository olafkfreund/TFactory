# Intent: a lane exiting 126/127 is graded reject instead of not_run

## Problem

A lane whose shell cannot find (127) or cannot execute (126) the test
interpreter never runs a test, yet `classify_pytest_failure` returns
`"unknown"` for it. The stability verdict stays `consistent_fail` and the
evaluator rejects correct tests (seen on the #1396 re-proof:
`python: command not found`). The triager then reports a broken lane as a
100% rejection of the tests.

## Proposed outcome

A lane run exiting 126 or 127 gets `failure_kind == "environment"`, so the
verdict becomes `not_run` (the #1344/#1394 path), never `reject`. The
`not_run` reason text describes an unusable lane environment generically,
not "no target URL". A genuine assertion failure is still a fail.

## Affected users and systems

`apps/backend/agents/stability_runner.py` (`classify_pytest_failure`),
`apps/backend/agents/confidence.py` (`apply_environment_override` reason).
Every lane (pytest, jest, browser, go, gradle, maven) reaches the classifier
through `StabilityResult.failure_kind`.

## Constraints

- Classify by exit code, never by prose inference (#1344 rule).
- Do not change how genuine assertion/import failures are classified.
