# Intent: a verify run that executed no test cannot claim a VAL level (#1583, #1582)

## Problem

TFactory#1583: for a FastAPI service all 14 generated api-lane tests failed at collection (`ModuleNotFoundError: requests`, pytest exit 2, `failure_kind: import`). Nothing executed, yet `verification.json` said "Verified to VAL-2" with VAL-0/1/2 `passed`, after 23.31 USD. Cause: the legacy docker runner image (`tfactory-runner-pytest`, `--network=none`, python 3.13) has `httpx` but not `requests`, and `val_block` counts a `flag` verdict as "ran and passed" even when the flag came from a test that never executed. This is the closed #892 symptom on a different path.

TFactory#1582: a spec whose subject needs Postgres/Redis cannot be verified (no service provisioning, no way to declare one in `.tfactory.yml`). TFactory still spends 10.40 USD generating tests that can only fail, ending 0/4 `ac_fidelity`.

## Proposed outcome

1. A run in which no test executed (all collection/import errors, or no verdicts) never reports an achieved VAL level above VAL-0; the block carries an explicit `verdict_class` (`infra` or `evaluated_empty`) and a reason.
2. A test that failed to collect because a HARNESS library is missing (requests, httpx, pytest...) is graded `not_run` (infra), so it is never handed back to AIFactory as a code defect (same principle as #1573).
3. `requests` is in the docker runner image.
4. `.tfactory.yml` can declare `services:` (postgres, redis). Until the runtime can provision them, a spec that declares them stops BEFORE generation with `generated_empty` and reason "unverifiable: needs services (...)", spending nothing.

## Affected users and systems

TFactory verify pipeline (`val_block`, `confidence`, `gen_functional`, `.tfactory.yml` schema), `docker/tfactory-runner-pytest`, AIFactory handback consumers.

## Constraints

- A subject-module import error (a real code defect) must still be handed back; only harness libs become infra.
- No live-cluster change, no secrets. Do not redo #1573.
- Go/JS/Java/Rust/shell lanes and MCP repo/branch (#1574) out of scope.

## Open questions

Decision (owner delegation 2026-11-18): service sidecar provisioning and a collect-only preflight are NOT built in this change; the recommended explicit "unverifiable: needs services" verdict (decision 3, fallback) ships first. Sidecars stay as follow-up on #1582, so #1582 is not closed.
