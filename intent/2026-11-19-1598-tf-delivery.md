# Intent: git_writer delivery with the PR branch already checked out (#1598)

## Problem

Since #1574/#1595 the ingest clone checks the PR branch out in the shared project clone (`/work/workspaces/<project>`). `git_writer` then runs `git checkout -B <branch> FETCH_HEAD` in the spec worktree and git refuses: "branch ... is already used by worktree". Verify succeeds but 0 tests are delivered (factory-lab-rust/java/cloud).

## Proposed outcome

Delivery commits and pushes the accepted tests to the PR branch even when another worktree has that branch checked out. #1595's stale-branch behaviour is unchanged.

## Affected users and systems

`apps/backend/tools/git_writer.py` push path; every ingest-driven verify.

## Constraints

Smallest change; no change to the clone logic; no credential change.

## Open questions

None. Decision (owner delegation 2026-11-19): take the issue's suggested fix, `checkout --ignore-other-worktrees`, the least invasive option.
