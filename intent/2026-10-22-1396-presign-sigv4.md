# Intent: packed lane push-back PUT returns 403

## Problem

With `TFACTORY_PACK_WORKSPACE=true`, every nested lane's result push-back
(`curl -T` to the presigned `TF_LANE_OUT_URL`) fails with HTTP 403 from MinIO,
so no lane result (junit, coverage) reaches the verify Job and every verdict is
`not_run`. The lane input GET works. Blocks #1160 step 5.

## Proposed outcome

The lane's `curl -T` push-back succeeds, the verify Job collects the lane
results, and the out object still carries the `role=workspace` lifecycle tag.

## Affected users and systems

`apps/backend/tools/runners/artifact_store.py` (S3 client),
`apps/backend/tools/runners/kube_sandbox.py` (`_pack_lane`, lane script),
packed verify runs on the cluster MinIO.

## Constraints

- Confirm the cause before fixing.
- Unpacked mode unchanged; `artifact_store`'s normal `put_object` path unchanged.
- Lane script and presign must agree: if the URL signs `x-amz-tagging`, the
  script sends exactly that header.
- Out of scope: the contract-less predicate gap (#1397) and the fixture flake.

None.
