# Intent: Task status for spec-ingest ids

## Problem

PR #1605 reads status.json only for the `project:spec` id form. POST /api/specs/ingest returns `task_id` = the bare spec_id, and the workspace dir is keyed by the project uuid. So GET /api/tasks/{id}/status still returns is_running:false, phase:null for every running ingest task on 0.13.0.

## Proposed outcome

GET /api/tasks/<spec_id>/status (and `<project-name-or-uuid>:<spec_id>`) reports phase and is_running from the spec workspace status.json.

## Affected users and systems

TFactory verify pipeline (web-server routes and backend agents); callers: cockpit, MCP proxy, spec-ingest verify runs.

## Constraints

Smallest correct change; tests that fail without the fix; no live-cluster action; repo-owned flakes and contracts keep winning.

None. Decided under the owner delegation of 2026-11-19 (recommended option).
