# Intent: A shell lane (bats + shellcheck) and skip means not_run

## Problem

For a bash script with a bats suite and a flake devShell (E2E level 6, task
`001-backup-rotate-sh-lab`), TFactory generated pytest wrappers
(`test_shellcheck_clean.py`, `test_bats_suite.py`, `test_flake_devshell.py`)
that `pytest.skip` when shellcheck, bats or nix is absent on the runner. A
fully skipped pytest run exits 0, so the mutation probe saw the unchanged
mutant "pass" and marked it survived, and the Triager rejected all three. The
ACs "shellcheck clean", "bats passes" and "flake evaluates" could never be
verified.

## Proposed outcome

- A `shell` language (aliases bash, sh) with a registered `bats` unit lane
  (`frameworks/bats`): `.sh`/`.bash`/`.bats` deliverables, `tests/**/*.bats`
  test paths, `bats` and `shellcheck` AC tokens, so the Planner emits real
  bats subtasks instead of pytest wrappers.
- The lane runs bats (TAP) and shellcheck inside the project's own
  `nix develop` when the repo owns a flake, else in a generated flake that
  provides bats and shellcheck.
- A skipped run is `not_run`, never a rejected test: TAP `# skip` in the shell
  lane, and an all-skipped pytest run (exit 0, nothing passed) in the pytest
  lane become exit 125, which the stability, mutation and confidence code
  already treat as "the test never ran" (#1573). Precedence: any failure wins
  over skips; only an all-skipped run (no pass, no failure) is not_run.
- The conversion covers every exit path: batched stability
  (`parse_pytest_exits`), batched mutants (`parse_mut_exits`) and the
  single-run parse, so a skipped mutant is NOT_RUN, not SURVIVED.
- The manifest `verify_commands` fallback is documented with its limit:
  `get_tool_for_lane` consults it only for languages absent from the registry,
  and the Planner still requires a registered framework.

## Affected users and systems

Planner vocabulary and validator, Evaluator, `nix_env` (lane runner, TAP
parser, pytest exit parsing), language descriptors, framework registry docs.
No change to Go/JS/Java/Kotlin lanes or the sandbox verdict rules.

## Constraints

- Follow the descriptor/registry pattern; build on #1573, do not redo it.
- `nix_provisioner.py` and the hub descriptors are vendored byte-exact: the
  `shell` toolchain descriptor is added TFactory-locally; a hub copy is a
  follow-up owned by the Factory repo.
- A skip must never be reported as a pass, and never as a test failure.

## Open questions

None. Decision (owner delegation): the shell descriptor lives in TFactory's
`languages/` for now (least risky: no cross-repo drift-gate change in this
round); hub promotion is listed as a follow-up.
