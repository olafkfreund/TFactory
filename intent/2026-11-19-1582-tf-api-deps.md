# Intent: python api lane always has client libs and a served SUT

## Problem

On 0.13.2, aifactory-demo PR #624 (FastAPI notes-api, no postgres/redis) had 9 api-lane tests fail at collection with `ImportError: requests`, and no SUT was served. #1611 routes a contract-less api repo into the nix Job (which has pytest, requests, pip and the self-served SUT) only when it needs postgres/redis. A plain FastAPI app with no services still takes the host runner, which has neither the client libraries nor a served SUT.

## Proposed outcome

A contract-less api-lane repo with a detectable uvicorn-served Python app runs in the nix Job with pytest, pytest-cov, requests, httpx, fastapi and uvicorn present and the SUT served, like the lab-cloud path.

## Affected users and systems

`agents/nix_env.py` fallback env and `evaluator._nix_verify_mode` (shared predicate).

## Constraints

Unit lane and non-python/node repos keep the host runner. A repo flake or contract env still wins. Smallest change. The get-note nix env build failure could not be read (workspace gone); the fallback uses the already-proven provisioner path.

None.
