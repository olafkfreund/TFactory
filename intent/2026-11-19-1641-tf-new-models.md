# Intent: Enable the new models in TFactory

## Problem

Phase Configuration, Insights and the backend shorthand map list old models (Opus 4.8, Sonnet 4.6, Haiku 4.5, GPT-5.x, Gemini 3.7). Current models exist for all three providers.

## Proposed outcome

New models are listed first and selectable per phase: Claude Fable 5.2, Opus 5.5, Sonnet 5.5, Haiku 5.5; Codex gpt-6.x; Antigravity gemini-4-* and gemini-3.8-flash-*. The shorthands opus/sonnet/haiku resolve to the 5.5 ids. Old ids stay selectable and resolvable.

## Affected users and systems

Portal users picking models; backend model resolution (phase_config), thinking config, usage cost estimate, prompt-cache floor, Insights provider lists.

## Constraints

- Saved settings and running tasks that name old ids keep working.
- Opus/Sonnet 5.5 reject `budget_tokens` (400): thinking must be adaptive for them.
- Prices only from the claude-api reference; OpenAI/Gemini prices stay unknown (no price entry).
- Provider detection for gpt-6.* and gemini-4-* must still route to codex/gemini.
- New Claude ids were proven in the tfactory pod via the Agent SDK before defaults switched.

## Open questions

None. Owner decision (2026-11-19): enable the new models; take the recommended option throughout.
