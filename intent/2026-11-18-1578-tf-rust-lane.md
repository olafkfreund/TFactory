# Intent: A Rust unit lane (cargo test)

## Problem

TFactory has no Rust lane. `cargo test` is not a registered framework, so the
Planner's validator rejects a Rust subtask as `invalid_framework`, `.rs` files
map to no language, and the Evaluator has no runner for them. The e2e campaign
(level 4, repo `olafkfreund/factory-lab-rust`: `Cargo.toml`, `src/lib.rs`,
`tests/`) could not verify a Rust deliverable. Go (#443), Java (#237) and
Kotlin (#1311) already follow the descriptor + in-cluster Nix lane pattern.

## Proposed outcome

- `.rs` is a deliverable extension for language `rust`; `Cargo.toml` is its
  manifest signal.
- `cargo test` is a registered unit lane (`frameworks/cargo-test`), so the
  Planner can emit Rust subtasks and the validator accepts them.
- The Evaluator runs the crate's tests in the per-task Nix dev shell (rustc and
  cargo already come from the provisioner's `rust` table), parses `cargo test`
  output into pass/fail counts, and never reports a pass for zero tests run.
- Mutation is out of scope, like the Go and JVM lanes (they build bundles with
  `mutation=None`): the existing `agents/lang_rust` probe is not wired to the
  Evaluator's three-argument runner and `cargo-mutants` is optional in the issue.
  The bundle reports mutation as not measured.
- The manifest `verify_commands` fallback is documented with its limit:
  `get_tool_for_lane` consults it only for languages absent from the registry,
  and the Planner still requires a registered framework, so it is a
  non-registered-language path, not a way around lane registration.

## Affected users and systems

TFactory Planner prompt vocabulary and validator, Evaluator, `nix_env` lane
runners, `lang_registry`, framework registry docs. No change to the Go, JS,
Java or Kotlin lanes, the sandbox verdict rules, or the #1573 runner image fix.

## Constraints

- Follow the existing descriptor/registry pattern; no new image path.
- `nix_provisioner.py` is vendored byte-exact from the Factory hub: do not edit it.
- Keep registry edits minimal (other teams touch TFactory).
- Cargo resolves crates at run time: the lane is `network: restricted` like Maven.

## Open questions

None. Decision (owner delegation, Codex review 2026-11-18): mutation (both
`cargo-mutants` and the assertion probe) is out of scope this round; revisit
when a Rust mutation lane is wired for all compiled languages.
