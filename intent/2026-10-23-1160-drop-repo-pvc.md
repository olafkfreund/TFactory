# Intent: drop the repo_pvc co-mount — packing is the only verify path (#1160 PR B)

## Problem

Verify has two workspace paths: the packed object-store path (#1159, #1160 PR A,
#1391, #1396) and the old RWO `repo_pvc` co-mount. The packed path is proven in
production: run `postdeploy-1023-packed-nix` on 0.9.36 with
`TFACTORY_PACK_WORKSPACE=true` (factory-gitops#298) ran the verify Job with an
emptyDir, ran both nested Nix lanes on the agent node with no repo PVC, brought
junit and coverage back, and accepted 3-0.

The co-mount path is still in the code, and the packed path still falls back to
it. A pack failure is fail-open: the verify silently co-mounts the RWO PVC and
pins itself to one node again, which is the defect #1160 exists to remove. The
toggle also lets the old path come back by config.

## Proposed outcome

- No verify Job and no nested lane Job ever gets a PVC volume for the workspace.
- A pack, presign or upload failure gives an honest `not_run`, with
  `failure_kind: environment`. It is never a pass and never a co-mount. The
  same holds for a lane whose input fetch or push-back fails.
- `TFACTORY_PACK_WORKSPACE` does nothing. If it is still set, TFactory logs once
  that it is ignored.
- The control-plane restore of the pushed-back tarball is unchanged.

## Affected users and systems

- `apps/backend/tools/runners/kube_sandbox.py`, `agents/verify_dispatch.py`,
  `agents/nix_env.py`, `agents/gen_functional.py`, `agents/equivalence_lane.py`
  (docstring), `agents/verify_workspace.py` (pack docstring), and their tests.
- The factory cluster after the next release: verify needs the object store
  (`S3_*` env), which it already has.
- factory-gitops still sets the toggle and `TFACTORY_WORKSPACES_PVC`; removing
  them there is a separate follow-up.

## Constraints

- `tools/runners/artifact_store.py` is vendored and must not change.
- The nix-store PVC (`TFACTORY_NIX_STORE_PVC`) is not the workspace and stays.
- Do not touch the cluster or factory-gitops.
- #1160 closes only after a cluster observation after the release, so the PR
  says `Refs #1160`.
